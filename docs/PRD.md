# 产品要求：全面验收与体验重设计

日期：2026-10-15。版本：1.0。当前目标来自用户本轮明确授权；docs/reference是历史资料，不覆盖本需求。状态：进入独立计划审查。

## 背景与目标

矩阵设备已具备12个桌面页面。用户要求自主逐功能验证、修复重复或矛盾的交互、采用Apple HIG风格重新设计，并让桌面、平板与手机尺寸的界面都可操作。每个修复验证后独立提交和push，不等待再次提问。

成功不是换色或一次149项通过：必须有逐控件正常与异常路径、目标隔离、真实设备效果、全部页面响应式与最终版本回归证据。

## 用户和范围

面向反复操作多台Android设备的企业用户、开发/测试人员和接口集成人员。保留原有12页的信息结构、功能、数据格式、HTTP契约和设备安全边界，简体中文名称可以精简；删除重复入口不删除独有能力。单设备、主控、列表勾选、应用独立目标仍须明确。

全部页面在范围内：设备、监控、界面检查、截屏、终端、应用、文件、文本、自动化、接口、工具、设置。显示名与内部Tag分离。列表模式和独立实时监控保持上轮决策。

## 用户流程和验收

| ID | 要求/用户流程 | 可验证的结果 |
|---|---|---|
| R01 | 启动、连接、选择、控制、退出 | 明确实际目标；原0保护不变；冷/热接入、取消、关闭/重启/配置均逐项验证 |
| R02 | 实时监控与主控操作 | 每台可见卡片有真实动态帧；暂停/离页/滚动释放会话；主控画面、按键和投屏不得落到另一个CurrentDevice |
| R03 | 节点和截屏检查 | 自动加载、选择联动、属性、导出、取色、裁剪/缩放/保存均有可检查产物；旧结果不能覆盖新目标 |
| R04 | 终端、文本、文件 | 实际输出/文本回读/文件SHA一致；空值、无效路径、离线、忙、取消、重试与历史不误导 |
| R05 | 应用和自动化 | 当前应用页真正完成独立目标、多选列表、安装/卸载/启停和进度；脚本导入/参数/运行/停止/日志与真实效果一致 |
| R06 | 接口、工具、设置 | 实际路由/端口/结果、能力限制、归档和配置回读逐项验证；501或禁用不冒充业务成功 |
| R07 | 全页面去重与布局 | 每个控件有单一明确职责；不同流程的共用底层能力不误删；无不可达功能、信息丢失或歧义目标 |
| R08 | 视觉与命名 | 浅色、低饱和强调、清晰排版、轻量反馈、细腻圆角和层级；名称短而明确，无假借苹果名词的晦涩命名 |
| R09 | 响应式 | 390×844、768×1024、1000×700、1440×900、1920×1080和390×640；所有12页及弹窗操作可达，无文字遮挡；字体放大/DPI另测 |
| R10 | 自主过程和交付 | 每项有日志、失败与修复复验、独立结论和Git提交；最终报告逐条映射要求，未验/受限项不计通过 |

## 约束和保守假设

- 当前产品为Windows WPF。平板、手机按相应窗口逻辑尺寸适配并测试，不虚称新增iOS/Android原生客户端；如确需在物理移动设备运行，必须另设技术方案，本目标不以仅缩放截图代替交互适配。
- 不改账号、支付、隐私权限、原实例0、共享ADB/防火墙/证书、系统全局代理或生产数据。独立测试实例1、2可用；先核验当前身份。只对本轮唯一的无账号测试包和临时文件执行可逆写测试，不清除用户抖音数据。
- 用户不再确认并不授权代为接受第三方协议或自动肯定尚未接受的基础设施风险。不能安全执行的动作保留缺口，继续其他任务；不得把拒绝路径写成真实业务通过。
- 现有未实现的私有agent/ROM相关能力不通过UI重设计凭空产生；仍逐项记录依赖、尝试和真实状态。目标是否满足要审计这些未完成项，不能擅自从总范围删去。
- 不安装全局字体或新UI框架，不引入付费依赖；保留现有技术栈和许可边界。无merge、release、deploy或自动清理分支/worktree。

## 优先级

P0为目标正确性、数据安全、功能可达、真实验证和交付证据；P1为全页面视觉、响应式、重复职责和企业工作流；P2为动效、细节与可访问性精修。本轮明确要求的P2也必须完成，不因等级低而跳过。

## 已知证据差距

主窗口MinWidth=1000；多个页面固定双栏。历史实机UI应用测试未经过当前批次应用页面。主控A、当前B时投屏可能读CurrentDevice，是待复现P0候选。149项和旧三尺寸Demo仅作对应范围基线，不等于全功能实机结果。

## 新增任务与验收

2026-10-16追加。原R01-R10及所有未完成验收保持有效，下表按用户要求从高到低排列；任务优先级不等同缺陷严重等级，低优先级也不得从最终范围删去。

| ID | 优先级/任务 | 范围 | 验收标准 | 依赖或前置条件 |
|---|---|---|---|---|
| R11 | P0/全功能测试 | 当前12页全部控件、正常/异常/取消/并发/目标变化路径，补双实例同步、独立测试包安装卸载、完整GUI及最终30分钟稳定性；新增功能随后补回归 | 每条需求及控件有步骤、预期、实际、结果和证据；问题具编号、严重性、状态与修复回执；必需功能未验或失败时不得完成最终验收 | A01控件目录、隔离配置、可靠测试入口、专用1/2和自有测试包；不得用旧VM捷径代替当前应用批次页面 |
| R12 | P1/终控台与RPA脚本控制 | 将终控台理解为现有设备工作区的统一任务状态，不新增第二套导航；本地脚本导入、校验预览、指定目标、分发、执行、停止后续、结果回传；AI通过MCP调用已授权脚本并关联指定应用的动态分析 | 合法脚本在每个指定目标产生可回读效果；非法包零执行；不同任务并行不串设备；重复提交去重、取消不再投递未提交动作，结果不明的写入先核验且不自动重发；MCP脚本作业能关联同目标抓包/运行证据；未实现的分析能力明确受限 | R11初始安全基线与现有脚本包/逐设备调度；仅AI子链路再依赖R13设计/最小接入及R14受控采集，不要求这两项先于本地脚本实现完成；未知脚本语言不自动执行，账号数据和任意主机代码执行不在默认范围 |
| R13 | P2/群控MCP调用设计 | 设计设备发现、能力查询、明确目标、脚本作业、控制、结果和采集工具契约；为R12提供可运行的最小接入验证，不把现有HTTP接口直接称为MCP | 工具清单、输入输出、授权、错误/取消/幂等、资源限额和兼容矩阵完整；真实MCP客户端完成握手、列工具、调用脚本并获取结果；逐台覆盖明确授权的在线目标，双实例不串扰 | R11安全契约、现有业务接口与R12脚本子契约，不依赖R12整项完成；“全部”指冻结的已授权集合，不等于自动启动23台或授予原0权限；两台通过不证明23路并发容量 |
| R14 | P3/模拟器抓包 | 先调查自带能力，再比较HTTP代理、HTTP Toolkit、VPN和原始包采集；选择指定实例/应用的方案，验证采集、停止、分析和导出，并纳入正式开发任务 | 官方资料和选型记录可追溯；自有应用的受控请求与记录逐条关联；目标隔离、超时/容量/退出清理验证通过；加密流量不能解密时明确仅元数据，不报明文成功 | 网络与权限清单、自有测试应用/服务、可信组件和R11目标证明；证书、VPN、系统代理及root等敏感变更不因无人值守而自动接受 |
