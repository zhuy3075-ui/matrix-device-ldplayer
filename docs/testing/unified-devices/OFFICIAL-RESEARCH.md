## 2. 能力结论

以下是官方文档层面的能力，不等于本项目已经实现或本机已通过测试。具体参数仍以链接原文及本机无副作用帮助输出为准。

| 需求 | 结论 | 项目处理建议 |
| --- | --- | --- |
| 关闭状态唤醒 | `launch`；`launchex`可同时启动指定应用 | 复用已有 CLI 服务，不以 ADB 在线作为启动前提 |
| 列表与状态 | 新版 `list2` 有宽、高、DPI；旧版只有前七项 | 保留兼容解析；拒绝 `list3` 的桌面哨兵 99999 |
| 新建 | `add` 分配新索引 | 创建前后比对目录，仅提交一次，失败不盲目重试 |
| 复制 | `copy` 使用指定来源 | 与空白新建分开；本轮不实施 |
| 单实例资源与型号 | `modify` 提供 CPU、RAM、分辨率/DPI、厂商/型号等 | 冷态白名单修改，重启后回读；不附带身份随机化或 root |
| 删除 | `remove` 清除实例数据/配置 | 仅提出方案，本轮不实施 |
| 应用安装 | `installapp` 支持本地 APK | 保留现有已验证安装路径及包版本回读 |
| 窗口排列 | `sortWnd` 是全局排列 | 不宣传成只移动所选实例；涉及原实例窗口须另行确认 |
| 暂不可用命令 | 新文档标注 `globalsetting`、`downcpu`、扫码、缩放、CLI 文件传输、应用数据备份和宏调用暂不可用 | 不因命令名存在就启用；传输/脚本继续走项目已验证后端 |

资源配置的保守白名单为 CPU 1/2/3/4 核、RAM 256/512/768/1024/1536/2048/4096/8192 MB。新文档要求修改后重启实例；旧教程建议先关闭再修改。采用更保守的“确认关闭、修改、启动、验证”流程。文档允许值不代表在当前主机上分配该值一定稳定。

设备型号是向系统/应用呈现的信息，不会改变物理 CPU、GPU 或真实硬件。验证应读取实际厂商/型号及系统页面，不把改名、写配置文件或 CLI 返回成功当成生效。

### 版本与文档差异

- 英文新版同页开头与末尾的 ADB 端口公式不一致；中文新版使用另一表述。端口公式只能生成候选地址，不能充当索引与真实设备的一一绑定证据。
- 2019 列表示例缺少新版的分辨率字段；应容忍已知格式差异，而不是把旧行判成“无实例”。
- 2023 教程仍列举部分命令，而 2026 新文档将它们标为暂不可用。优先新文档并进行独立实例验证，不能将旧教程的存在当作当前可用证明。
- GUI 有高级多开参数，不等于 CLI 已提供稳定接口。尤其不能用目前暂不可用的全局配置命令实现全部 GUI 优化，或直接改厂商私有配置格式冒充 SDK 对接。

## 3. “17 台与 2 台”项目根因

这是主代理源码核对结论；本文未重新执行目录查询或实机压测。

1. 雷电目录记录和 ADB 可操作设备是两个集合。目录中的实例数量不能推导运行数量、接入数量或已授权数量。
2. 此前验收配置只授权 `emulator-5556`、`emulator-5558`。`AdbDeviceBackend` 构造函数把 `AdbAllowedSerials` 冻结到集合，发现时先过滤，之后才读取 guest 信息。因此只出现这两个设备符合既有安全边界，并非 ADB 只能支持两台。
3. 原先 `LdPlayerService` 的 `list2` 目录与 ADB 设备目录独立，旧界面没有对其余目录项自动建立并验证串号绑定。
4. `MatrixRuntime.CreateAsync` 可以先发现授权设备，但旧 `App.xaml.cs` 仅在 demo 或 `AutoConnect=true` 时调用窗口 ViewModel 的刷新。`AutoConnect=false` 下，运行时已有快照也可能尚未同步到界面。

对应源码位置：

- [`AdbDeviceBackend`](../../../src/MatrixDevice.Core/Devices/AdbDeviceBackend.cs)：构造函数及 `DiscoverCoreAsync`。
- [`MatrixRuntime`](../../../src/MatrixDevice.Host/MatrixRuntime.cs)：初始化发现及雷电绑定。
- [`App.xaml.cs`](../../../src/MatrixDevice.Desktop/App.xaml.cs)：窗口初始化与自动刷新条件。

这些路径从本文所在目录应以仓库根目录定位；源码可能随本轮实现变化。上述根因描述的是优化前的基线，不应覆盖后续验收结论。

**不得将目录中的 17 条记录写成“17 台已接入”或“17 台并发压测通过”。** 当前既有实机证据仅覆盖此前独立验收范围。更大容量必须另外核定资源、授权目标、并发任务和实测数据。

## 4. 模块合并建议

本节是待实施设计建议，不是已完成说明。

- 界面合并为一个设备工作区：同一行显示雷电目录身份、运行状态、ADB 接入状态、授权/绑定状态和可用动作；不保留两张互相矛盾的总数。
- 复用 `LdPlayerService`、ADB 后端、逐设备队列、脚本调度和现有 API，不复制第二套执行器。界面统一不代表混淆 host 生命周期操作与 guest 读写权限。
- 目录层可显示未启动或未授权实例；只有经过实际进程/串号/transport 校验的授权设备才可以截图、输入、传输或执行脚本。不得为了显示全部条目删除 allowlist 保护。
- 统计分别标明“目录总数、运行中、已接入、待授权/异常”，搜索和分组从同一快照派生。未知、离线和未授权不能使用相同的“连接成功”外观。
- 当前范围只绑定一个明确的雷电安装目录。不根据 GUI 跨版本宣传推断不同安装目录的相同 index 是同一设备，也不默默执行 Android 版本迁移。

## 5. 自动启动与接入状态机

建议区分两个入口：“启动并接入”是显式用户命令；“刷新”只观察和核验，不启动关闭实例、不安装应用、不改系统设置。

```text
目录存在且已关闭
  -> 用户明确启动
  -> Starting：对冻结的目标提交一次 launch
  -> WaitingAdb：实际 PID/出生时间、运行状态与候选传输逐项核对
  -> Binding：验证唯一串号、服务身份、transport 和授权范围
  -> Ready：目标 boot_completed 确认，设备快照已同步界面

任一阶段身份变化 -> Stale/Failed：停止旧代次任务，不复用旧绑定
用户取消或启动超时 -> Cancelled/Failed：保存阶段、耗时和错误，不循环 launch
```

`launch` 完成只代表命令返回，官方没有承诺此时 Android、应用或 ADB 已就绪，也没有承诺可仅凭退出码判断结果。已运行目标应走重新发现/核验，不能顺手重启。启动轮询采用截止时间、退避和取消；超时后展示最后完成阶段，不靠固定睡眠宣称成功。

自动注册不意味着可以替换共享 ADB 服务。保持既有服务 PID/出生时间保护；发现服务被替换时停止本程序写入并报错，不执行 kill/start-server。原实例不在本轮授权内时，不读取其 guest，也不为测试重启它。

实例启动后发现新的串号，应在既定授权策略内完成实际绑定，未获授权则停在“待授权”。已配置但当前失效的绑定必须撤销；不能继续给旧 transport、旧进程或猜测串号发命令。

## 6. 刷新与竞态建议

- 启动时始终把已有安全快照同步界面；“是否自动发现/接入”与“是否呈现已有状态”分别处理，避免关闭自动连接后整个列表空白。
- 一次刷新整合 host 目录和已授权 ADB 快照，记录时间与各子系统错误。某一个失败时标明该部分陈旧，不把另一部分静默覆盖成空列表。
- 合并重复刷新并提供取消/超时，不并发创建多个发现循环。普通刷新不得执行启动、重启或共享服务恢复。
- 新代次到来时取消旧脚本/传输的后续步骤，清除旧截图、节点及输入坐标。慢响应只在目标身份与请求代次仍一致时更新当前界面。
- 保留选中/搜索/分组语义；目标消失时撤销主控和写入能力，而不是自动切换主控到另一台设备。
- 压力测试将刷新频率、节点读取和截图频率分别限额；记录 CPU、可用内存、句柄、操作延迟与失败率，不用“全部条目已列出”代替吞吐测试。

## 7. 新建、复制与资源配置

新建空白实例可作为独立功能实施候选；“新建”与“复制”不能共享一个默认会克隆的按钮。创建前检查空间与名称，执行后通过目录差异核对唯一新项。若 CLI 非零退出但已经新增，记录不一致并停止重试，不再制造重复实例。

复制会携带源环境，可能包含账号、登录态、配置和个人数据。需用户选择确切来源、理解复制范围并接受空间/数据风险；优先冷态源以降低一致性风险。这是项目保守约束，不声称官方保证热复制事务一致。本轮不实施或实测复制。

CPU/RAM/分辨率/厂商型号配置需显示修改前后值及重启影响，保持单实例操作锁。拒绝隐式追加设备身份随机化、root 或网络修改。修改失败不能显示已生效；回退到旧值也属于再次配置/重启，应事先定义授权及日志，不自动扩大到原实例。

官方雷电 14 GUI 可以选择/管理不同 Android 版本，但公开 `add` 参数未承诺版本切换接口。**本轮不实施 Android 切换、跨版本迁移或复制。** 高级节能、虚拟磁盘及全局音频/FPS设置继续标注为需要官方 GUI 或另行调研的范围，不直接覆盖厂商配置文件。

## 8. 删除方案与人类控制

删除仅作为后续方案，不在本轮实施或测试。建议届时显示完整目录路径、index、实例名、数据风险及备份状态，要求用户确认确切目标；执行前再次检查身份和关闭状态。目录变化、身份不符、忙碌或目标为受保护原实例时拒绝。

删除不能用“清理测试环境”作为默认授权，也不能在创建/配置失败时自动补偿删除。不得调用全局关闭来满足单实例删除前置条件。备份镜像包含系统和数据，必须作为敏感本机产物保存，不进入源码仓库或公开日志。

## 9. 后续验收要求

1. 离线测试覆盖新旧列表格式、哨兵、目录与授权数量不同、重复刷新、启动超时/取消、进程/transport 代次变化和过期响应。
2. 使用已授权独立实例实测关闭状态唤醒、就绪、接入与界面显示；保存命令回执、阶段耗时和实际绑定证据，不操作原实例 guest。
3. 新建和资源配置只有在用户同意范围内验收，分别记录唯一新目录、配置前后值及重启后的实际效果。
4. 复制、删除、Android 切换、跨安装目录管理和 17 台压力测试均保持未实施/未验收，不计入本轮通过率。
5. 独立 verifier 对证据与声明逐项核对。任何真实设备验证未做，就明确写未做及原因，不将 demo、静态代码或官方文档标为 PASS-LIVE。
