# 实时监控实施与验证报告

日期：2026-10-15。状态：R5专用实例1/2的11项实机回归通过；根离线137/137通过。结论限定双路、短时及下列明确操作，不是23路容量或长期稳定性验收。

## 范围

- 左侧实时监控，默认已连接设备的画面墙，支持资源列表/全部目录。
- 每张可见、已授权、已核验的运行实例独立视频；不需选择或放大。每通道只保留最新帧，UI最多8次/秒呈现，源端上限10帧/秒。
- 主机CPU/物理内存，实例Player+VBox CPU与工作集，约2秒采样，当前会话最多15分钟趋势。
- 独立监看选择；双击/窗口图标打开现有雷电窗口；节点页面首次自动加载与快速切设备补偿。
- 暂停、资源模式、滚出、切页、连接替换和退出释放相应视频；关闭实例不会因浏览而启动。

未包含：原实例0、其它guest验证、4/23路容量、长期浸泡、GPU/网络/磁盘、应用FPS、音频与卡片内输入。视频回归只用专用实例1/2的系统设置，不对抖音账号做任何操作。

## 实现与取舍

固定官方scrcpy-server3.3.4及SHA256，经现有受保护ADB transport直连localabstract socket；不运行外部ADB/scrcpy客户端，不使用共享forward。唯一临时jar/scid/nonce标识会话，关闭视频后先等待自然退出，必要时仅对有完整出生与命令行证明的本次PID发TERM。身份不明/权限失败不扫杀，标记清理未确认并阻止后端内继续叠加。该阻断尚未跨程序重启持久化。

H.264经本程序启动的FFmpeg解码为BGRA；不使用PNG轮询替代，不生成重复FPS帧。组件不在源码包中；来源与固定摘要见README。原产品私有视频握手没有恢复，新路径是明确独立实现。

更简单的截图+资源列无法满足逐卡连续画面要求；screenrecord有180秒分段及故障清理限制，未选为默认；未验证23路前不扩大容量承诺。每卡解码进程简洁、隔离，但随通道数增加会产生CPU/RAM成本，后续扩大前需重新做容量试验。

## 修复清单

1. 资源读取不用GetProcessTimes未定义的存活进程ExitTime；同句柄以WaitForSingleObject检查存活。
2. 视频启动请求/OKAY/关闭stdin均纳入清理；未取得启动证明时保留证据并阻止重连。
3. 正常取消FFmpeg的退出竞争不误报错误；嵌套的清理未确认仍保留为失败。
4. PID读取、TERM与退出复核发生错误后，只有第二次精确确认该PID目录不存在才算退出；仍存在或权限失败继续拒绝。六种消失/权限反例覆盖。
5. UI异步等待后复核运行时/监控代次；重试等待旧清理任务，回调带会话代次；身份失效立即清旧帧。
6. 多卡停止先同时触发取消再等待，不逐卡累计清理延迟。恢复暂停时重启UI计时器；错误日志不被历史帧提示覆盖。
7. 节点加载中切设备保留待加载请求；视频不会写入节点截图或改变群控目标。
8. 恢复复跑发现本地取消与正常EXIT0/EOF完成竞争，已在隔离视频工作树确定性复现；本次限定一轮最小修复并独立复核。只有正常EXIT0/正常EOF完成后检查取消，异常任务、非零退出和清理未确认仍保留错误；公共API未变。修复提交4002b798，在根整合为d1895bf。反例只锁定完成分支，未穷尽所有线程调度。
9. R4补齐逐轮窗口/可见性、帧序号/哈希、最近资源时间、隐藏后同会话画面变化、节点截图归属、三程序集SHA及独立helper/decoder退出证据。R4全目录首轮触发过于绝对的1.5秒必增断言；R5保留12秒窗口和变化/身份/完整时长门禁，允许短暂同序号但拒绝回退、会话更换、未来或未知时间。离线回归覆盖这些边界，旧失败不改绿。
10. 监控页主机、到帧、等待及资源提示原先直接格式化UTC，存在8小时时差显示。仅显示处转换为本地时区；UTC存储和帧龄计算不变。离线检查正常/历史帧与资源提示，实机observations新增hostDisplay用于复核。
