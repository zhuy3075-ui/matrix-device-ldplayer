# 正式构建移除演示数据

目标：正式入口、程序集和发行首页不提供演示设备/Mock 实例、演示启动、测试 MCP 或演示画面；无设备时显示真实空状态，不制造在线设备。保留 `tests/` 中为回归所必需的隔离夹具，不删测试换取通过。只调整当前源码树，不重写公开历史，不删除用户本机数据或授权配置。

## 事实与方案

原生产 Core 内含两台演示设备及虚拟雷电目录，Host/CLI 可实例化，Desktop 编入四十余个验收 partial，MCP 仅 Demo。仅删除 JSON/图片不足以解决运行时仍可产生假设备的问题；简单删除整个测试工程会失去回归能力，也不采用。

推荐把生成器、桌面验收 partial 和仅 Demo MCP 移入 tests。默认解决方案只构建真实产品；测试必须显式 `EnableTestSupport=true` 且使用独立 artifacts 输出。默认 Host 拒绝 demo=true，Desktop/CLI 拒绝演示和验收参数，已有 IsDemo 身份隔离字段和真实设备守卫不改为宽松模式。

## 依赖顺序

1. P0 定义并验证正式入口拒绝 Demo、未知参数、缺失路径；无演示类型/测试入口的程序集合同。
2. P0 移动夹具并隔离构建，保留原 248 个正式回归和 MCP Demo 测试，不接入真实设备；构建默认产品与独立测试输出。
3. P1 替换演示图片/策略/旧源代码快照；只使用无授权、无实例的真实空状态渲染，不伪称视频连接或实机验收。
4. P1 独立审查默认程序集、失败边界、离线测试、差异范围与文档。最多三轮针对性修正，不进行压力、安装卸载、长期或完整物理 GUI 测试。
5. P1 验证完成后回主工作区精确整合；保留四份脏文档及两张英文图片。仓库同步沿用用户本轮的正式源码清理与推送范围，不创建 Release/标签或改写历史。

## 验收

- 正式 Core 无 DemoDeviceBackend / DemoLdConsoleRunner；Desktop 无 smoke/验收执行入口；正式解方案无测试 MCP。
- `--demo`、`--smoke`、`--verify-*` 在配置/ADB/窗口初始化前拒绝，退出码非零；默认服务不伪造设备。
- 测试构建不能写普通 bin/obj，保留离线回归断言；测试 DLL 的存在不代表进入正式程序集。
- README 和新截图无演示数据，旧图片/源码汇总中不继续提供旧生成器。测试夹具仍明确标为测试，历史日志及提交不伪造删除。
- 真实连接、实例启动、API 及身份门保持，原未完成验收项不关闭。
