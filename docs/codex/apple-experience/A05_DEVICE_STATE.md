# A05a 设备状态与选择职责隔离

日期：2026-10-15。基线2b1fe6eb0db53ee7fc4ef5e4d63d546f8d459d8d。状态：实现、独立离线验收及主仓最终复验通过。A05b设备/监控/主控正文响应式仍属必需后续，不以本修复代替。

## 已知事实与根因

详情状态下拉TwoWay绑定WorkspaceViewModel.StatusFilter；VM默认DeviceView与Unified列表受它影响，Monitor又枚举同一个过滤视图。详情关闭只Hide，过滤继续存在，可能跨页隐藏设备、删除监控卡片并停流。详情还有第二套全选/清空/行复选框，直接改群控授权选择。只改名称或关窗时重置筛选不能解决职责耦合。

## 推荐方案与边界

1. 详情只保留显式单设备选择、四子系统信息、名称编辑与保存。使用独立未过滤ListCollectionView，不重新添加群控选择或分组入口；保留既有分组元数据。
2. 设备列表有唯一可见状态筛选，只影响该列表显示。固定分类基于实例/设备实际字段与既有Connected证明，不读操作phase推断真实状态，不放宽任何启动、配置、写入或授权门禁。
3. 明确关闭须非启动中、安卓未启动、双PID非正、双窗口句柄为零；残留进程/窗口、过渡值或全停但设备仍报Ready等矛盾快照归未知，不猜“可操作”。0/99999保护语义保持。
4. 监控从未过滤统一目录和原有范围生成卡片。列表筛选不改变监控epoch、卡片对象/签名/资格、监看选择或连接所有权；暂停、离页和滚出清理仍沿原规则。
5. 运行分类与行显示一致，原操作阶段诊断保留，不用含混的重复“就绪/已连接”入口。已发现状态不能改称待发现。

更简单的关窗重置方案被拒绝：仍存在双选择入口，打开期间依然跨页耦合。完全删除筛选也被拒绝：丢失原有有效能力。新全局状态框架不采用：现有页面局部视图足够，无需更换Core/Host/ADB/HTTP或持久数据结构。此修复跨多个显示边界，不适用最多5文件的minimal-fix限制，按既有A05常规阶段实施，不借机做宽度或主题重构。
