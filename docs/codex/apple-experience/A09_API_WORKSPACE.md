# A09b2 接口工作区

## 背景与目标

基线`29e4037`已交付接口启动事务修复，属于上轮progress，不重复交付。当前按R06/R07/R09继续接口页面的完整控件路径、职责、失败反馈和六尺寸正文，不改已经验证的Host事务或HTTP契约。

已知事实：全停命令实际停止网关和设备接口，却称“停止网关”，且只有device接口时按钮禁用；四个VM生命周期操作只在成功后刷新地址/摘要。Busy结束本来就刷新命令，不能把所有CanExecute未更新误当根因。请求结果没有捕获上下文，在途修改参数后旧响应仍可回填。固定260高的请求区、固定输入宽度是布局候选，须实际复现，不先宣布裁剪已证。

## 范围与非目标

- 保留同一VM/Runtime、四个原生命周期命令及原发送命令、五按钮、两个ComboBox、三个TextBox、同一DataGrid与六列/绑定，保留勾选、单设备选择和双击复制地址。
- 四个生命周期操作在实际完成或失败后刷新真实地址及摘要；全停不受当前选择限制，设备停止仍按原Targets。全部目标已有接口时禁用重复启用；不新增第二个停止入口。
- 明确名称为“启动网关”“停止全部接口”“启用设备接口”“停止设备接口”“发送请求”；地址列如实称设备接口地址，不误当网关地址。摘要包含实际设备接口数量，不恢复已删除的全局“当前设备”区域或搜索栏。
- 复用原输入/命令/表格对象，只在本页重排：宽正文并列两区，窄正文上下并允许受限滚读；表格和多行输入有界，内部横向/纵向滚动可达末尾，动作最低44逻辑像素。不改共享主题、其它页面或导航Tag。
- 仅自有shown WPF/Demo及loopback。不得操作真实设备/ADB、全局代理、账号或用户服务；不恢复AP042/AP045外部GUI失败分支。Tools页面、真实GUI/DPI、原生剪贴板及最终实机验收继续后继。

## 第一性原理与方案

问题不是重复增加按钮，而是现有停止职责、可用条件和反馈不一致。推荐修原VM谓词及四操作finally，保留原异常和部分成功事实；不回滚已成功的设备接口，也不扩大网关全停范围。仅修改文案不能修device-only禁用和陈旧地址；新增独立全停按钮会造成第二套职责，故不采用。

请求发送前冻结Runtime、协议/实际所属端口、设备协议的serial、方法/路径/正文及本地revision。相关输入、目标或实际endpoint变更立即失效旧结果；返回后只向相同上下文发表。普通目录刷新而endpoint未变时不无故清结果。只在TextChanged清空不够，因为在途旧响应仍会重写。

保留本机相对路径限制、禁止自动重定向和30秒期限，并局部显式UseProxy=false、验证构造后的URI仍为冻结的127.0.0.1端口；不改操作系统代理。默认UseProxy只属缺显式合同，尚无代理泄漏实测，不能预先记安全事故。此revision不冒称解决外部直接调用Manager同端口快速重启的全部交错或跨Runtime授权问题。

失败模式包括：批次A成功/B随后离线、占端后重试、空/部分/全部接口已有、请求在途切目标和参数、坏JSON/相对路径、Busy及传输门、长内容撑高和窄屏表格不可读。更简单的一列布局可以只解决部分宽度，不能替代业务修复；整页无限拉伸、删列或复制控制面板不采用。
