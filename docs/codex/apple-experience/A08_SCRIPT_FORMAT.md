# A08a / AP-044 脚本包格式明确拒绝

## 目标与范围

基线为 `2ca79ce2cb49ece68724b3ff3fcf108500a6c52a`。自动化页把 `.json` 列为脚本包，但实际加载器只接受包含 `manifest.json` 和 `script.json` 的 ZIP。本阶段统一入口与实际能力，不扩展脚本语言。

仅修改 `ScriptPackageService.cs`、`ScriptsView.cs`、正式 `Program.cs` 测试及本文。GUI、真实模拟器、ADB、顶层 JSON 支持、参数替换、Probability 语义、目标冻结、取消协议和任务架构不在范围内。

## 契约

- 普通顶层 JSON、Python/JavaScript 文本、随机二进制、空文件和损坏非 ZIP 由实际 `Load` 拒绝，返回 `DeviceException`、HTTP 状态 `400`、代码 `1007`，中文明确说明当前支持 ZIP 脚本包而不支持顶层 JSON/通用脚本。
- 仅把创建 ZIP 归档时的 `InvalidDataException` 归类为归档格式错误；文件缺失、共享冲突等 I/O 错误、归档内 JSON 错误和原有验证错误保持原边界。
- 按内容判断而非后缀：合法 ZIP 即使名为 `.json` 也保留兼容。合法附带资源不被新增拒绝或解压执行。
- 保留压缩 16 MiB、归档 128 条目、声明解压总量 32 MiB、单 JSON 实际读取 4 MiB、10000 步骤、1000 参数等现有限额及旧动作/路径校验。
- 文件选择器只将 `.jxscript/.zip` 列为支持格式；“所有文件”不授予执行任意内容的能力。
- 导入不执行步骤。只有显式调度合法加载结果才产生效果；拒绝路径不得产生 Demo 点击。

## 最小方案与取舍

推荐仅在 ZIP 构造边界转换归档格式异常，并修正选择器。仅移除 `.json` 更简单，但不足以覆盖“所有文件”及服务调用。拒绝新增任意 JSON/Python/JS 执行器：格式/参数语义尚未冻结，会超出 A08a 的安全边界。

## 红绿验收

先保留生产 `Load`，新增实际出口测试并运行一次现有 `tools/Build.ps1 -Verify`；预期只有六种格式拒绝契约因原异常类型/信息失败。随后最小修复，原测试不改，运行一次同命令。

新增测试还包括：合法 ZIP 使用 `.json` 后缀且含附带资源，经实际加载和现有调度器得到 `Tap 1`；拒绝路径保持 `Tap 0`；文件缺失/共享冲突、内层 JSON、原动作验证及原归档大小门禁不被误归类。旧往返、路径越界、缺条目、重复启动和取消测试逐字保留。

每轮使用上级 `.tools/dotnet/dotnet.exe` 绝对路径，保存独立 ignored artifacts 原始 stdout/stderr、退出码、deadline 和源 SHA。单轮 300 秒，超时终止仅该轮自有进程树；不重试凑绿。实现者冻结后交独立审查，不能自行最终批准。
