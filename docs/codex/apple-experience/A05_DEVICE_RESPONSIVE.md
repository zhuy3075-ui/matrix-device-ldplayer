# A05b1 设备列表与主控适配

日期：2026-10-15。基线6c4adce8f975fa9e0cfe1d71bb5fea9c63d1459e。状态：已独立离线验收并通过主仓最终代表路径，本阶段提交保存。文案修复已单独推送；本阶段只处理设备/主控正文，不含监控卡片或其它页，也不取代后续实机验收。以下迭代记录保留当时状态，最终结果只看本报告末节。

## 事实、根因与范围

设备操作列前已有397逻辑宽，小屏初始视口看不到按钮。按钮32高、WrapPanel与48行高会使第三动作换行被裁；默认单元格左右各10padding和边框，不能直接把列设为44就称44命中。主控固定分走300宽，正文高度绑定视口，窄屏及展开投屏后的自然滚动不足。Down保存旧映射，Up用新布局，resize可能被误当滑动。

推荐沿原WPF组件局部重排：

- 紧凑列表以选择48、操作约148在前，冻结两列；局部覆盖两列padding/margin，三个现有动作均有44×44完整命中区，不换行。左右留白12，真实信息视口至少120；名称和原全部信息可横向滚动。桌面恢复适当文字布局，不整页缩放或删字段。
- 使用同一个DataGrid与主控面板。实际workspace约920及以上并排，否则主控占同一工作区、暂隐列表；原返回/关闭在固定标题区可达，正文唯一ScrollViewer自然展开，图片有界，所有按键/同步/投屏末端均能滚到。
- 重排不调用SetMain/OpenMain/CloseMain，不重设Current、主控、勾选或输入代次；返回不重建列表，保持可实现的滚动位置。已有隐藏勾选须可识别，启动所选仍按原明确选择，不暗改授权。
- resize、离页、失活、丢鼠标捕获取消未完成手势；正常Up先冻结源/目标/代次再释放捕获，防止LostCapture重入清空同步目标。正常tap/swipe保留原映射、尺寸/代次/忙/离线/脚本门禁。

更简单的只横滚不适配被拒绝：首屏关键动作仍不可达。复制“手机版主控”被拒绝：会产生第二套控件和身份状态。新UI框架或全局主题重构不采用。此阶段是已计划跨组件响应式，不套用5文件小修限制；只改相关Desktop页面/启动验收入口/正式测试，不改Core/Host/API或真实配置。

## 实施观察

已取得390×640真实红测：原按钮X从408开始，越出374宽客户区，实际高32；日志在实现工作区`artifacts/apple-device-responsive/red-390-640`。初步布局绿色只覆盖默认行几何，不是完整验收；六尺寸长列表、三动作、主控和手势/调度证据尚待补齐，不能以此标完成。

实现/独立预审发现的重点：Margin必须按稳定父级宽度决定，避免用自身ActualWidth切12/22引发反馈振荡；跨冻结区改DisplayIndex前先归零FrozenColumnCount；selection表头同样受全局Padding10,7影响，须局部处理并实测44命中；新入口实际尺寸和校验必须使用同一InvariantCulture解析。旧条件式`panel is ScrollViewer`必须改显式正文视口硬断言，不让新panel类型静默跳过。长主控标题不得挤光正文，所有原动作和长信息仍需可读路径。

调度屏障仅用于Demo的Desktop已接纳任务，真实后端调用可能在屏障释放后才开始；派发计数不等于ADB wire计数。输入正常例须等真实handler记录的Task完成，再读Demo副作用；Tap N本身不能区分Tap与Swipe，应同时核对不可变InputSnapshot。

UI初步合同6源冻结patch摘要`9D021D79B6E2D72417E853ED0A48CC016D8FF352889DC82C242F225A7F5155DD`；实现工作区`layout-build2.log`记录150/150（51.34秒），随后两处Down清理/视口断言修改另编译成功。该次测试不等于最终全部源码通过；完整专项文件由独立测试作者在另一worktree补齐，最终仍须同一源码的全量重建、六尺寸及非实现者验证。1000预检截图已看到列表和主控末端；不以目视替代长列表/完整命中断言。

专项迭代已区分下列事实，仍未达到最终通过：

- 表头44勾选框的边缘实际命中`PART_RightHeaderGripper`，局部去padding不足；固定选择列宽度后边缘命中通过。操作列同样固定，信息列仍可调，不把全部列锁死。
- 保护行的低层VisualHit取到了不可见RowHeader拖拽部件，属于夹具过滤缺陷；修正可见性过滤，保留禁用状态和完整几何要求，没有把保护行重新启用。
- 信息列`ElementStyle`有默认非null值，原本仅给null样式列装trim/tooltip的代码未生效；数字Tooltip的类型转换修正后仍失败，已按实际默认值修本地样式，保留State详细提示。不能只归因为数字比较错误。
- 普通返回及快速返回/重开/返回通过；实际ScrollContentPresenter滚轮路由已Handled并改offset后，旧ContextIdle恢复任务覆盖了新的滚动锚点，取得真实红证据。局部修复需保留未完成快照、校验恢复代次，并由真实输入取消过时恢复；不把普通布局ScrollChanged误当用户意图。
- r4曾误将构建与一轮启动交叠，该轮不作冻结binary证据；构建结束后的独立重复仍复现相同Tooltip失败。所有失败轮次保留，最终只接受构建完成后同一源码/产物的完整矩阵。

主控两个同步开关选择局部44命中，不改变全局CheckBox/Expander样式或同步语义。新增专项r5正在补正文滚动中断、同纵横比但像素尺寸改变的Demo画面负例；它们不是实机旋转或物理输入证明。最终报告另行记录完整源码摘要和实测计数。
