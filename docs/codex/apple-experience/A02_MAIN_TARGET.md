# A02：主控投屏目标一致性修复

日期：2026-10-15。状态：代码修复通过独立离线验收，主仓最终界面回归通过。关联AP-001 / NATIVE-01；本报告不代表全部功能或真实外部投屏验收。

## 根因与最小处理

主控面板/按键使用MainDevice，但NativeView的可执行性、启动和嵌入使用CurrentDevice；在A为主控、列表选中B时，可能误用B的投屏。原实现的Demo红测实际抛出“主控A没有投屏进程，却允许嵌入当前设备B的进程”。

修复仅3个源文件：Views/NativeView.cs、MainWindow.xaml.cs、Views/NativeTargetSmoke.cs。统一使用明确主控，不回落当前设备；单源门禁与群控勾选/同步开关解耦。一次操作固定runtime、DeviceRow、串号、generation、transport与输入代次；确认后、身份核验后、窗口等待后重新检查，失效即拒绝，不转向新目标。外部路径及投屏参数使用确认前的不可变设置快照。进程所有权固定PID、出生时刻、可执行路径；嵌入和退出清理核验同一自有会话。

没有引入新的全局选择模型，也没有改后端/API。仍保留外部ADB客户端风险确认；不会自动确认或启动它。
