## 事实与最小方案

现 DebugView 使用 star+300+270 三列，工具按钮继承全局32高度；公共 Toolbar 只换行，不重排正文。390、768等尺寸的实际图像可见面积尚需先取证，不能把源码推断直接当已运行失败。

推荐一个持续存在的正文 Grid，按稳定正文容器的实际宽度调整行/列：起始预算为正文宽920及以上三栏，640到919为画面加右侧树/属性上下两行，低于640使用“画面 / 节点 / 属性”分段，默认画面。分段只切原控件可见性/位置，不新建Tab或重复控件；原 Viewbox/Canvas/Image/Tree/TextBox 与 TreeItem/Rectangle 映射保持。阈值按图框及按钮实际边界验证，可以调整但须保留原红及变更理由。

四个原工具局部保证44逻辑单位命中区，窄屏分段各44；不更改全局Theme或把设备像素覆盖框扩成假44目标。树头选择区域需要足够高度；共享树箭头等细节仍由全触控/A10单独审计，不将本次部分44证明扩为全部控件可用。

更简单方案为三块全部纵排，但390×640易形成多重滚动并使画面离开首屏，不推荐。另一个窄屏两段方案把树与属性分半，较少入口但长属性可用高度更小；选三段让每个任务获得完整正文高度。拒绝整页缩放、复制第二套树/属性、在resize重新截图/重建节点或更改真实导航语义。

失败模式：以子内容或滚动条宽驱动断点导致振荡；隐藏区留住焦点；隐藏/重排使滚动或文本选区无故归零；工具栏占满正文；布局回调重建映射或发设备请求。使用稳定正文宽、原对象和实际状态/请求断言约束，只有实证的滚动问题才补最小恢复，不预造通用框架。

设计参考为Apple官方[布局指南](https://developer.apple.com/design/human-interface-guidelines/layout)和[分段控件指南](https://developer.apple.com/design/human-interface-guidelines/segmented-controls)：适应可用窗口、保持信息层级，将紧密相关的视图用等宽名词分段。本页是Windows工具的局部检查区，不复制macOS窗口外观、不以HIG替代实际命中和正文测试，原12页导航保持不变。
