# A14a2 逐目标脚本任务

## 背景与目标

现有调度器以 serial 保存当前运行，后一次执行覆盖前一次状态和日志；ADB 在每条动作进入队列前重新取得 transport，未冻结整次作业身份。本阶段复用原脚本编译器、执行循环和逐设备队列，增加可追踪、可单独取消的任务，并接入自动化页面。不是另建执行引擎，也不替代原 GUI、双实例和最终稳定性验收。

## 范围与边界

- 每个接纳的目标有唯一 JobId，冻结 serial、目录 generation、transport 和明确的 Demo/真实模式，以及包 ID、版本和编译后的步骤/参数。
- 每条设备动作在真实后端的原 serial 队列出队后核验目录身份并固定提交时的 transport。身份不符时不发送动作，不回退串号选择；不递归进入同一个队列。
- 提供逐任务状态、步骤、开始/结束时间、错误、日志、结果和取消；有界保留终态历史，不淘汰活动任务。取消请求与任务排空后的终态分开。
- 旧 RunAsync、串号状态/日志投影和 Stop(serial) 保留兼容；新增提交遇到已占用设备时明确拒绝，不把旧重复启动的 CompletedTask 当接纳。
- 自动化页面显示任务记录，按选中的 JobId 查看日志和取消；切换设备选择不改变已接纳任务。保留原“停止所选”的当前设备选择语义，两种取消的作用域明确区分。
- 不新增 HTTP/MCP 路由、任意代码执行、持久恢复、代理/CA/VPN 设置或账号操作；不触碰实例 0、共享 ADB 或用户配置。
- 提交接受点在编译、参数、预取消、身份和设备占用检查之后。此前拒绝不生成任务记录或清空旧日志。真实目标必须有非零 transport，Demo 例外由受信运行时/后端模式决定，不能凭调用者目标字段绕过真实后端。
- 单目标提交独立接纳或明确拒绝；页面多目标逐目标汇总接纳与拒绝，仅对已接纳目标保存参数，不先写入全部目标。元数据保存失败须明确说明任务已经接纳，不能伪称未运行。
- 保留既有安全前置：所选集合含尚未连接设备时整批拒绝，不悄悄只运行在线子集；在线集合中的设备占用或身份冲突逐目标报告，不阻止其它空闲有效目标。
- 任务历史最多保留 100 条终态，按结束顺序淘汰最旧记录；活动任务不淘汰，每个任务日志最多 500 条。旧串号投影不覆盖独立任务历史。历史为当前进程/运行时会话，不承诺重启恢复。

## 验收标准

1. 两目标差异化运行产生各自实际 Demo 效果，第三目标不变；包编辑或选择变化不改变已接纳快照。
2. 取消任务 A 不影响 B；已结束 A 的旧 JobId 不能取消相同 serial 的新任务。取消延迟/排队/在途任务时须等待真实工作排空，后续动作不执行。
3. 提交前、排队中及步骤之间的 generation/transport 变化均拒绝旧身份。随机端口自有 ADB 协议测试证明没有向新 transport 或 serial fallback 派发副作用。
4. 非法参数、非法身份、设备忙和取消的提交不新增 Running/任务/后端副作用；终态与有界历史可查询，观察者异常不破坏任务生命周期。
5. 原 193 项断言与四项 VM 参数案例保持；新增核心和 STA VM 案例实际执行，独立 verifier 复核并复验。GUI 未执行的控件不得标为通过。

## 方案取舍

推荐扩展原 Scheduler 和原后端队列：增加的状态集中在一个执行生命周期，维护与测试成本可控。更简单的仅增加 GUID 和 UI 列表不能防止重连后动作发往新 transport，不能满足身份隔离。拒绝外包整段脚本到另一个同 serial 队列，因调用原后端会递归等待；也不建立第二套脚本引擎或修改所有设备 API。

失败模式重点为取消竞态、终态过早、旧任务取消新运行、队列等待期间身份变化和日志串任务。若现有队列不能在实际动作前固定身份，必须调整边界而不能以提交前检查代替。

## 验证记录

### 契约与实现

`ScriptJobTarget` 为不可变目标，`SubmitJob` 返回 `ScriptJobHandle(JobId, Completion)`；`GetJobs/GetJob/GetJobLogs/CancelJob` 用 JobId 查询或取消。未知或淘汰 ID 查询为 null/空日志，取消为 false，不回退串号。原 RunAsync 与新提交共用一个 serial 占用表，串号停止仍只作用当前运行。JobChanged 报步骤，不额外重放旧 StatusChanged 的 Running 事件。

Core 的 `IIdentityPinnedDeviceBackend.BindIdentity(catalog)` 返回只支持启动、点击、滑动的身份绑定能力；实际后端固定报告其 Demo/真实模式。真实动作沿原队列执行，出队后和实际 shell 发送前都复核身份及冻结 transport，包含 SetDeviceAsync 等待后的窗口。返回文本来自实际 StartApp 调用，逐步汇入 Result，总 UTF-8 上限 16 KiB，保留有效 Unicode 并明确标注截断；无输出的已完成作业显示“已完成”，不代表应用业务成功。

自动化页保留脚本包导入和参数表，增加“运行记录”页签：目标身份、状态、进度、脚本、完整 JobId、开始/结束时间及结果；选中任务查看其独立日志。“取消此任务”按 JobId；“停止所选设备”沿当前设备勾选，两者提示明确作用域。结果折叠区有有界滚动，长输出不无限挤占任务列表。运行时热换解绑旧订阅并清空该会话列表；关停等待调度器和 VM 持有的观察任务，不承诺跨运行时保存历史。
