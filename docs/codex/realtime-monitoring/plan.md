# 实时监控实施建议

状态：仅专用实例1/2的R5实机11项通过，根离线137/137通过；4/23路及长时测试不在已完成范围。现有.NET10/WPF为基线，未启用自动loop，不运行外部ADB客户端。最终证据与限制以专项REPORT为准。

## 技术策略

把身份目录、独立采样缓存、监控呈现分开；复用现有明确实例绑定和窗口身份检查，不复用截图方法中修改节点上下文的副作用。宿主资源不需要guest命令，guest图像采集走现有授权后端。数据样本即数据，不把UI选择或IsOnline当作身份凭据。

推荐新增专门监控页，画面优先，每个可见合资格卡片独立视频播放；更简单的资源加截图方案不能满足最新实时要求，不作为替代交付。先验证成熟视频链路的只读、无音频/剪贴板与共享ADB兼容，再做有限多路；拒绝未实测就默认23路和无限并行截图。不先建通用遥测平台或健康评分。

## 文件职责建议

- Core：不因监控改动协议或放宽身份校验；若确有复用需求才增加不可变监控样本契约。
- Host/Monitoring/HostResourceSampler.cs：主机CPU/RAM与已核验进程采样，真实时差/首样本/进程重启处理。
- Host/Monitoring/MonitorSampler.cs：资源和备用快照采样、代次丢弃、趋势缓存，不依赖Desktop选择状态。
- 视频链路：成熟投屏采集与解码、按实例唯一会话、只保留最新帧、有界缓冲、可见性调度、真实到帧统计；具体验证后确定依赖和模块位置，不把现有NativeView窗口嵌入等同于已经支持多卡视频。
- Desktop/MonitorViewModel.cs及Views/MonitorView.cs：监看选中项、排序/筛选/状态、设备墙与趋势，不修改群控目标。
- Desktop/Views/WorkspaceShell.cs：新增单一“实时监控”入口，复用现有外壳。
- Desktop窗口组件：增加显式“打开既有实例窗口”路径，不把ShowAsync的自有恢复权限扩大成任意窗口接管；检查PID出生时刻及HWND，不按标题。
- Tests：计时/进程读取可替身、采样队列/错误/陈旧/代次验证；Desktop smoke涵盖新页和不干扰节点上下文。

以上是职责位置建议，实施时先读实际模块再定文件名，不为满足目录形式制造无用类。

## 风险与恢复

读指标的权限不足、共享GPU/渲染进程归属不清时显示未知，不能猜测；截图占用导致操作延迟时降频/跳过监看请求，任务优先。连接替换期间停止旧guest采样。退出仅清理本程序采样器，恢复自有隐藏窗口，不关闭模拟器。

若必须新增外部组件、扩大授权范围、启动/停止实例、接受外部ADB风险、保存画面/远程上传或声称新的并发能力，先停下请求用户决定。只读设计、实现、验证与源码持久化分别留证，不对未实施部分标完成。
