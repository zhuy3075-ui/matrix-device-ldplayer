# 实时监控设计

日期：2026-10-15。状态：本文保留需求与设计基线；已交付的双路范围在R5通过11项，最终证据见专项REPORT。页面表中的设计候选不等于全部已实现；历史设计基线dc57168。用户已确认“画面优先”，并要求每张卡片无需放大即可看到实时画面。目标是在打开多台雷电后，集中观察页面、状态和资源变化，并能定位异常及打开对应窗口操作。不启动新的自动化目标，不读取CODEBRAIN。

## 产品方案

推荐新增左侧“实时监控”，位于“设备管理”之后。设备管理负责启动、接入、分组、配置；实时监控负责只读观察、趋势、异常与打开既有窗口。共用实例身份目录，但不共用群控选中目标。节点调试负责元素定位，不与监看轮询耦合。

首版默认“实时画面墙”：进入监控后，每张可见、已授权且运行中的卡片自动建立独立视频流，在卡片原尺寸持续显示，不以点击、选中、放大或弹窗为前提。资源列表是辅助视图；选中显示趋势与详情，双击或点击窗口图标打开既有雷电进行人工操作。关闭实例不因浏览而启动。原外部投屏路径仍须完成共享ADB风险确认；本轮新监控采用既有服务直连socket，不运行外部ADB，因此不触发该外部客户端风险路径。官方helper推送和仅1/2测试已获本轮用户授权。

截图轮询只作用户明确允许的备用降级，必须标“快照预览/视频不可用”和最后成功时间，不满足实时视频验收。原对话设计稿使用历史截图与示例指标，仅表达布局，不能证明连续视频能力；本次调整的是需求，不把静态原型冒充视频演示。

更简单方案：给现有设备管理增加资源列与截图轮询，成本低但不满足用户最新确认的逐卡连续画面，不能替代本轮目标。拒绝未验证容量就默认23路全开、靠高频PNG冒充视频、按窗口标题接管窗口，以及把静态画面直接判为卡死。

## 页面设计

| 区域 | 内容与行为 |
|---|---|
| 顶栏 | 搜索、分组、异常筛选；监控采集开关；采集档位；沿用蓝白侧栏风格 |
| 主机摘要条 | 主机CPU、物理内存已用/总量、本机/运行/已接入数量；不用“配置内存”冒充已用内存 |
| 画面墙 | 稳定尺寸设备卡：编号/名称、连续视频、视频连接/设备连接独立状态、最后收帧时间、实际接收FPS、宿主进程CPU/内存和已有脚本状态；未选中卡片也播放 |
| 选中详情 | 当前监看对象的大预览、最近15分钟CPU与内存趋势、最后成功时间、最近错误、已知任务状态、打开窗口与节点调试入口 |
| 事件条 | 连接断开、截图超时、资源阈值告警、自动降频及恢复；可跳到目标设备，去重同类事件 |
| 资源列表 | 编号/名称、连接、画面年龄、CPU、工作集、脚本、最近采样、窗口入口；按资源排序，选中后保留详情 |

单击仅改变监看选中项，不设置CurrentDevice/MainDevice、不勾选群控目标、不向guest发送输入。双击只发起显示已运行实例窗口的显式用户动作，不启动实例，不自动部署scrcpy。展示窗口前核验实例代次、SDK路径、播放器PID及出生时刻、HWND所有者；不按标题匹配，不操作原实例0。Windows可能限制置前，应提示“已请求显示窗口”而非保证抢焦点。

监控页默认只读，不提供关闭、重启、安装、删除等危险快捷操作；显式打开后进入既有雷电交互窗口，用户可以正常使用鼠标键盘。进入节点调试才切换明确的调试上下文并自动抓取首轮截图与节点；截图和树并非跨时刻仍有效的实时定位依据，页面变化后旧结果标过期，不向新页面复用坐标。

## 指标与口径

| 指标 | 首版设计与限制 |
|---|---|
| 整机CPU | 两次主机CPU累计时间差，0..100%整机口径；首笔/失败无值，不能填0；处理器组超过64逻辑处理器时检测并拒绝不完整统计 |
| 整机内存 | 物理内存总量/可用/已用；与实例配置的RAM配额分开 |
| 实例CPU | 已核验Player+VBox进程CPU差值之和，除以逻辑处理器数量与实际采样时长；明确“宿主进程占整机CPU”，不是App CPU |
| 实例内存 | Player+VBox工作集合计，单位MiB/GiB；标签/提示说明含共享页，不是安卓已用内存或虚拟机独占RAM；不把各实例工作集直接相加当整机占用 |
| 页面画面 | 已授权设备的独立连续视频流，保持原宽高比；检查真实帧到达及播放，停止后保留最后帧并变暗标记。可选PNG备用必须明确为快照 |
| 任务 | 仅显示系统已有脚本运行/停止/失败状态和日志；未建立业务心跳时不宣称业务成功 |
| 前台App | 可选后续项；需独立低频guest查询、Android兼容及未知状态，第一版不默认频繁dumpsys |
| GPU/网络/FPS | 不承诺实例级GPU、网络或App渲染FPS；视频接收FPS必须按真实到帧计数。FPS上限不是实际FPS，静态页不产生新帧时不据此误报卡死 |

### 术语

- 快照预览（snapshot）：周期性读一张画面，必须展示实际画龄。
- 实时投屏（video stream）：连续视频帧；需要独立采集/解码通道，不能靠页面名称宣称已经实现。
- 工作集（working set）：进程当前驻留物理内存中的页，可能包含共享页，不是配置RAM配额。
- 数据陈旧（stale）：超过本轮安排的采集期限仍没有成功数据，不等于设备卡死。

## 调度与可信度

以下均为待验证参数，不是已达到的性能承诺：主机/实例宿主指标每2秒采样，实例目录每5秒更新；视频可先评估低分辨率、每路5至10 FPS上限作为巡检档，不将帧率上限当成实测值。每实例最多1路监看流，限制同时起流数量，保留有界最新帧缓冲，不堆积解码队列。每个当前可见、合资格卡片均须自动播放；不能只给选中项建流。

离屏设备可暂停解码或降低流量并标“离屏暂停”；滚回可见区时自动恢复，先有真实新帧才恢复“实时视频”状态。离开页面可停止视频、保留低频资源采样，回来按可见设备恢复。资源不足时明确显示降频/容量不足，不能悄悄把视频替换成PNG还标实时。要同时监看更多台可调整网格密度，但必须先测对应路数的容量。

“可见”包含进入视口及部分进入的卡片；快速滚动使用短暂保留/迟滞，避免反复建流。有限并发起流只限制同时建立连接的数量，不表示只让前几张卡片持续播放。等待容量的卡片显示“等待视频”，不计为实时通过。

视频连接与画面变化分开判断。隐藏、最小化或失焦后的源端渲染必须分别测试；未变化不能单靠FPS归因，状态无法确认时提示“画面源状态待确认”，不反复播放旧帧冒充新帧，也不偷偷显示雷电窗口恢复渲染。断流立即标连接中断；仅在授权、实例及共享ADB身份都未变化时有限重试，收到新有效帧才恢复实时标记；身份变化直接停止，不自动接纳新代次或重启ADB。

设计前原设备群控每5秒最多4台截图，23台理想完整轮转约30秒；它不能满足逐卡实时视频要求。现已新增独立视频采集/解码与卡片播放，不把旧截图轮转算视频。用户可暂停监控，暂停后显示最后成功时间；23路性能上限必须实测，不能因目录有23台就宣称23路实时可用。

host资源、guest视频及备用截图分别调度。脚本/传输运行时，host采样不因普通UI Busy全停；监看低优先级、有界缓冲，绝不影响操作顺序或自动重试写入。连接运行时切换、身份变化或服务代次失效时暂停guest读取并丢弃旧结果。不得直接复用现有RefreshAutomaticScreensAsync的末尾ClearNodes行为，否则持续监控会破坏节点调试。视频监看默认无音频、无控制、无剪贴板同步，不因点击卡片或拖入文件而操作guest。

每个画面/资源样本包含运行时代次、实例索引/代次、进程出生时刻、串号、成功时间、值/错误。各指标独立标记新鲜度；重启后CPU基线重置、曲线断开，不续接旧代次。首次等待、失败、未接入与0值必须区分；旧画面不能继续标“正常实时”。

画面不变仅提示“持续未变化”，不能自动判“卡死”；静态设置页、隐藏窗口渲染暂停、截图失败和业务停滞要区分。告警首版只提示，不自动重启/关闭实例；阈值待配置，例如主机CPU>90%或物理内存>85%持续30秒，使用持续时间及恢复迟滞避免反复抖动。

默认保留15分钟内存趋势环形缓存，文本事件按现有日志限额管理；不默认录屏、保存连续截图、上传画面或完整节点/窗口转储。历史落盘、录像或远程上传需另行确认。

## 验收

白话：进入画面优先监控后，不点卡片、不放大，所有可见的已授权运行卡片都能连续显示对应页面变化；资源同时更新。单击/双击不会操作错设备；断线、暂停、旧数据有明确状态；运行脚本时仍能观察且不破坏任务；静止页面不会误报卡死。

技术：
- 经批准的专用实例分别运行可识别的连续动画/计时画面，在同一窗口同时显示至少2台，再测4台；整个验收不选中或放大任何卡片，记录独立到帧、序号、延迟和录屏证据，确认变化持续且实例映射正确。仅PNG更新不通过此项。
- 雷电主窗口隐藏和可见两种状态均验证视频更新；静态画面、视频断开、自动重连、离屏再回来分别验证，不以静态页无新帧直接判失联。视频与ADB在线状态不得混为一项。
- 对已放行配置及经批准的2/4路负载，所有可见卡片都必须通过逐卡首帧耗时、动态延迟、断流恢复和资源开销检查。展示23张时，2/4张通过不能代表整页23张通过；容量不足的等候卡明确不算通过。
- 用无缓存、离线、未授权、截图超时、CPU首采样及采样失败样本分别验证状态；不能返回假0或假FPS。
- 用两个具有相同窗口标题的实例验证索引/PID/出生时间/HWND归属；重启后拒旧样本和旧窗口，原0及未授权guest读取次数为0。
- 监控切换/选择/采样前后群控目标、CurrentDevice/MainDevice及节点树不被隐式改变；主动进入节点调试除外。
- 单路采样超时不阻塞其余实例，无积压；离页/暂停停止新画面请求，旧请求完成不能覆盖新代次。
- 先2台，再4台，最后按用户批准和资源余量扩大；记录P50/P95画龄、采集耗时、跳过/失败数、监控自身CPU/RAM及操作延迟。没有目标负载实测，不宣称23路性能达标。
- 桌面1440×900、1920×1080和1000×700检查文字/图像/曲线不遮挡，原型另检查窄屏；业务阶段要使用真实运行设备截图验收。
