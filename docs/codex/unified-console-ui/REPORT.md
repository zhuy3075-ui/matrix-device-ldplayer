## 应用流程

1. 左侧选择已接入且在线的模拟器，可多选；与设备群控、主控及单设备目标相互独立。空选中不回退到旧CurrentDevice。关闭、受保护或未核验目标不可用。
2. 选择变化后合并短暂重复刷新，逐台读取实际列表。每行包含模拟器名、串号、包名、名称、版本、类型；同包在不同实例保留为不同行。
3. 安装：选择一个或多个APK，生成明确的模拟器×文件计划，确认框列出数量、全部目标及文件，提醒可能覆盖安装。任务逐项执行，刷新列表；包名未解析时明确标记“命令完成、列表已刷新、APK包名未核验”，不冒充精确安装验证。
4. 卸载：只处理实际勾选的应用行，绝不把A的包名扩展到B。确认框列出全部串号/包名并说明删除数据不可撤销。执行前重新读取并保护系统应用，执行后重新读列表确认目标包不存在；仍存在或查询失败均为失败。
5. 每项显示等待、执行中、已完成、命令完成、失败或取消，汇总区分部分失败。只有卸载消息依据实际列表声明已核验移除，启动/停止/清数据命令完成不等于运行效果已核验。停止后续不会中止已提交项的结果观察，也不承诺回滚；已完成项保留真实结果。更多菜单保留启动、停止、清数据，清数据同样确认且保护系统包。

## 实现与边界

新增Features/Applications/ApplicationBatch复用现有IDeviceBackend，不引入新的ADB客户端、APK解析器或外部依赖。运行时、串号、连接代次、transport及选中目标在确认前冻结，确认后及逐项执行前后复核；已有授权/原0/99999、脚本/传输/API互斥边界不放宽。应用页通过ViewModel.ExecuteAsync统一忙状态及API写入守卫，逐项写现有日志。

当前后端应用名称可能只是包名，未取得版本时显示未提供；不宣称已提取APK图标、标签或包名。安装进度按已完成任务数，不伪造单文件字节百分比。大型全系统列表的反复核验成本较高，本轮未做实机性能承诺。

启停快捷操作仍保留原有不弹确认的交互；安装、卸载、清数据需确认。公共确认文案按动作区分，启停文案直接通过纯确认生成用例核对，不因此新增启停弹窗，也不将旧不可达文案当作用户已遇到的缺陷。写命令取消零I/O的证据来自ApplicationBatch的确认拒绝测试，不只依据界面提示字符串推断。

统一实例操作下拉与表格共用同一目录对象，但使用独立无过滤CollectionView，避免“勾选A+B、筛选隐藏A、取消B”后实际A与下拉空/B不一致。单目标选择不隐式改主控或群控勾选；非雷电行清空SDK目标。操作成功/异常都即时同步统一列表，不只等待5秒轮询。节点自动加载改按Tag，不依赖删除旧Tab前的下标。

单设备目标同样采用独立无过滤CollectionView，不复用目录默认筛选视图。全局分组隐藏正在操作的设备后，无论目标下拉可见或折叠，都不清空CurrentDevice、主控、节点、图片和脚本参数；设备目录列表仍采用原有单向绑定与非空显式选择，避免筛选产生反向空写入。

窄窗口的顶部操作区独立滚动，按客户区高度为下方目录保留至少140像素可见高度及边距；不把整页套滚动容器掩盖列表。应用与任务表的绝对宽度列有等值最小宽度，空间不足时横向滚动，不将序列号压成难以区分的前缀。关键截图前等待渲染，并核验全局分组控件仍在客户区内。
