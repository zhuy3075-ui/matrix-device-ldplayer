# 统一控制台界面与应用管理

日期：2026-10-15。目标：实施用户本轮四项界面修改，不开展新的模拟器压力、卸载或账号测试，不读取CODEBRAIN。

## 需求与范围

1. 删除所有可见搜索输入：全局设备搜索、设备目录弹窗搜索、节点过滤和应用搜索；删除控件、提示及绑定，不用不可见控件占位。保留分组/状态选择等非搜索控件。
2. 删除全局“当前设备”展示及设备目录重复展示，回收对应行高。内部CurrentDevice、授权、代次及操作目标模型必须保留；需要单设备操作的页面使用明确的目标选择，不让命令变成盲操作。
3. 只保留一个设备管理入口、一个目录和一套选择模型。取消全部设备/高级管理切换及独立雷电页；保留启动/接入、启动全部、新建、冷态配置、关闭/重启、应用快捷操作、文字/按键、分组、三视图、同步及原生窗口能力。低频命令可内联折叠，不是另一个导航页。
4. 复用已有“应用管理”侧栏位置，升级为独立显式目标集合，按(serial, package)展示列表；查看多台已安装应用、批量安装、按明确行卸载、必要确认、逐项进度/错误/取消、完成后核对刷新。不得把A的应用列表当作B的卸载指令，不得未勾选时回落到CurrentDevice。

## 验收与约束

- 所有实际导航页及设备弹窗无搜索输入绑定、提示或当前设备展示区域；移除后的内容自然占满，不留空壳；保留全中文和1000/1440/1920布局。
- 导航与真实Tab数量一致且无雷电实例/高级管理页；节点自动加载及其它页面定位按Tag而不是旧页序号。
- 统一目录选择与生命周期操作对应同一实例，原0/99999保护、共享ADB/实例代次、资源提示与破坏操作确认不放宽。
- 应用选择与群控选中项互不偷换；操作前冻结运行时、目标串号/代次及包名，执行前重新校验；断开/重连拒绝旧任务；系统应用卸载拒绝或明确保护，不自动清数据。
- 批次逐项记录等待/执行/成功/失败/取消，失败不计成功；安装不凭CLI退出码冒充新列表验证；卸载确认列出精确目标与数据损失。
- 默认仅离线、demo和本程序自有窗口验证。真实安装/卸载、启停实例和共享服务变更不在本轮授权内。正常程序替换先请用户保存关闭，保留现有1/2/3配置。

## 方案与取舍

推荐在现有WPF模块内外科式整合：共用已受保护的设备后端，统一目录与选择，应用页使用明确的目标/应用行，复用全局忙状态和日志。更简单的仅删标签或给旧应用页加下拉会留下重复目录和目标错配，拒绝。全新Web前端/通用任务平台增加迁移和维护成本，不采用。旧API、脚本和视频协议不改。

主要风险是初始化依赖ldGrid等旧页面字段、硬编码Tab下标、卸载目标错配及异步返回覆盖新选择。通过初始化/选择映射、Tag定位、不可变批次快照、代次检查及独立审查覆盖。若不能保留任一有效功能或需要扩权操作，先停下说明，不把隐藏旧页面当合并完成。
