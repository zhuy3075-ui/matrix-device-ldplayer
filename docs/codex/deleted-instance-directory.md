# 删除雷电实例后的设备目录同步

日期：2026-10-18。范围仅为用户反馈的“雷电实例全部删除，设备页仍显示旧离线设备”；此前全面测试目标保持暂停。

## 根因和约束

- `DeviceCatalog`有意保留离线历史，以维持断连通知和连接代次；不能直接清空离线项，否则会误伤USB/TCP设备，并可能导致同串号重连代次复用。
- 统一设备页在雷电实例缺失时，把保留的旧设备重新作为普通设备加入目录。仅隐藏表格行又会留下其他页面的设备目标和主控引用。
- 本机配置明确包含截图三串号与实例的绑定。修复只依据当前运行时冻结的唯一绑定，以及最后一次成功读取的雷电目录；不按品牌、名称、串号前缀推断。

## 推荐方案

在Runtime发布目录中排除“明确唯一绑定、对应实例在成功目录中已不存在、且当前离线”的设备。保留内部Catalog历史、元数据、授权与绑定。成功LD刷新后立即复用VM缓存同步，清理旧行、选中、当前设备与主控，不等待后继ADB发现成功。

更简单但不足的方案是仅过滤表格，其他页面目标仍残留，因此不采用。直接删除Catalog行影响身份代次和重连，复杂度与风险超出本次范围，也不采用。

查询尚未成功、失败或取消不能当作成功空目录；后续失败也不能让已确认删除的旧离线项复活。仍存在但关闭的实例、普通离线设备、未绑定串号、在线设备和歧义重复绑定应保留。

3. P0：同一回归旧红→新绿，覆盖成功空目录、普通离线保留、关闭但未删除、未初始化/失败/取消、删除后失败不复活、冻结配置、身份历史以及旧选择/主控清理。
